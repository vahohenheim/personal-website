# Internationalization

**Summary.** The site is served in English (default) and French, with the locale as the
first URL segment. It uses no translation library: texts are plain TypeScript dictionaries,
and the current locale is read on the server through `next/root-params`, the mechanism
documented by Next.js 16. `proxy.ts` only deals with URLs that have no locale.

## Locales

Declared once, in [lib/i18n/config.ts](../../lib/i18n/config.ts): `LOCALES`,
`DEFAULT_LOCALE`, the `Locale` type, the `hasLocale` guard and `OPEN_GRAPH_LOCALES`.
Routes, metadata alternates, the sitemap and the structured data all follow `LOCALES`.

## Choosing the locale: `proxy.ts`

[proxy.ts](../../proxy.ts) is the Next.js 16 name for middleware. Its `matcher` makes it
run only for URLs that have no locale and are not a file, an API route or a Next.js
internal: localized pages are served by the CDN without invoking it.

1. The URL already starts with a locale: nothing happens.
2. Otherwise it redirects (307) to the same path under a locale, chosen in this order: the
   `NEXT_LOCALE` cookie, the best match of the `Accept-Language` header, then `en`.

The language switch is the `fr · en` link of the header
([HeaderNavComponent](../../components/header/header-nav.tsx)): a plain link to the same
page in the other locale. On click it writes the cookie, so that a later visit to `/` lands
on that choice.

Internal links always carry the locale and the trailing slash
(``href={`/${locale}/resume/`}``). A link without a locale would cost a redirect.

## Reading translations

In any Server Component or server-side helper:

```tsx
import { getDictionary, getLocale } from "@/lib/i18n/dictionaries";

const locale = await getLocale();
const { home } = await getDictionary();
```

Both functions read the `locale` root parameter, so no `locale` prop is passed down and
pages do not read `params`. An unknown locale ends in `notFound()`.

Client Components cannot call them:

- Pass the locale or the texts they need as props, as the header does for its nav.
- When no props are available, use a context. `error.tsx` receives no props from Next.js,
  so the root layout wraps the page in
  [ErrorMessagesProvider](../../lib/i18n/error-messages.tsx) and the error boundary reads
  it with `useErrorMessages()`.

## Dictionaries

[locales/en.ts](../../locales/en.ts) defines the `Dictionary` type;
[locales/fr.ts](../../locales/fr.ts) is typed with it. A missing or extra key in either
file fails the type check and the build.

Dynamic entries are read by indexing with an identifier:
`dictionary.companies.list[company.id].name`. See
[content/resume-data.md](../content/resume-data.md).

Some texts contain HTML (`<b>`, `<br/>`) and are rendered with `dangerouslySetInnerHTML`.
This is acceptable only because they come from these two files. Never pass external data
through those components.

Texts that are not visible but are read aloud (labels of icon-only links and buttons, the
portrait description) live under `a11y` and follow the same rule as visible texts: never
hardcode them in a component.

Placeholders: `{year}` in `footer.copyright`, replaced by the footer, and
`<1>…</1>` in `error.description`, which marks the LinkedIn link.

The legal texts live in `locales/legal/` and are plugged into the dictionaries (`legal.sections`,
`cgv.terms`). They use inline marks (`[text](href)`, `**strong**`…) read by a parser, not
HTML. The terms of service exist in both languages (`cgv.fr.ts`, `cgv.en.ts`, from the
Markdown sources of `docs/legal-handoff/content/`); the French version prevails. See
[features/legal-pages.md](../features/legal-pages.md).

## Adding a locale

1. Add it to `LOCALES` and `OPEN_GRAPH_LOCALES` in `lib/i18n/config.ts`.
2. Create `locales/<code>.ts`, typed as `Dictionary`.
3. Register it in `lib/i18n/dictionaries.ts`.
4. Update the language link in `header-nav.tsx`: it is written for two locales (`fr · en`).
5. Add it to the `matcher` of `proxy.ts`. Next.js requires a literal there, so the
   locales are repeated: a locale missing from it still works, but every page view then
   runs the proxy for nothing.
6. Create `locales/content/<code>.ts` with the texts of the home page and the resume,
   and `locales/legal/notice.<code>.ts` with the legal notice.
