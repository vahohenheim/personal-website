# personal-website

Personal website of Valentin Bourreau (`valentinbourreau.com`): a home page, an online resume, a services page with prices, a legal notice and the general terms of service, in French and English, generated at build time, plus a contact form for leads stored in Neon and forwarded to lotus (Valentin's private management app), a private admin area (leads and audience figures) and two daily crons (copy of Vercel Web Analytics to Neon, retry of the leads lotus has not confirmed). Next.js 16.

This file holds the working rules. The explanations are in [docs/](docs/README.md): start there.

## Working rules

- **Language.** Everything written in this repository (code comments, docs, commit messages) is in English.
- **Next.js docs.** The version-matched documentation ships in `node_modules/next/dist/docs/`. Read the relevant guide there before changing routing, caching, metadata or config. `AGENTS.md` is generated by `next dev`; do not edit it.
- **Checks.** Before handing work back, `npm run check`, `npm test`, `npm run build`, `npm run test:smoke` and `npm run test:e2e` must all pass. CI runs the same five commands on every push. Details: [docs/development/code-quality.md](docs/development/code-quality.md).
- **Tests.** A change comes with its tests, in the same change. Tests never reach a real database or a real service: in-memory stores, and a stand-in for lotus. A new stored value, environment variable or protected route gets a guard test. Details: [docs/development/testing.md](docs/development/testing.md).
- **Deployment.** A push to `main` deploys to production. Commit and push only when asked. Details: [docs/operations/runbook.md](docs/operations/runbook.md).
- **Versions.** Every change to the app bumps `version` in `package.json` (and `package-lock.json`) in the same change, following semver: major for a redesign or a break, minor for a feature, patch for a fix, a content or a docs change. Write its release notes in `docs/releases/v<version>.md` (first line: the title). When the change reaches `main`, the Release workflow tags the merge commit `v<version>` (annotated) and publishes the GitHub release from those notes; the manual commands of the runbook are a fallback. Details: [docs/operations/runbook.md](docs/operations/runbook.md#versions-and-releases).

## Documentation

**Maintenance:** every change to the site updates, in the same change, the pages of `docs/` that cover it, and their `last_updated`. To find them, look for the modified files in the `related_code` headers. If no page covers the topic, create one and add it to the index in [docs/README.md](docs/README.md). A change is not finished until its documentation is.

## Structure

`app/` holds routing only; everything else lives in `components/`, `lib/` and `locales/`.

- Import through the `@/` alias. A relative import may reach a sibling folder; ESLint rejects `../../`.
- A component used by one page goes in that page's `_components/` folder; a shared one in `components/`.
- Details: [docs/architecture/overview.md](docs/architecture/overview.md).

## Routing and translations

- Every route is under `app/[locale]/`, whose layout is the root layout. Locales are declared once, in `lib/i18n/config.ts`. The `matcher` of `proxy.ts` repeats them as a literal: keep both in line.
- On the server, read the locale and the texts with `getLocale()` and `getDictionary()` (`@/lib/i18n/dictionaries`). Do not pass `locale` down as a prop between Server Components, and do not read `params` for it.
- Client Components receive the locale or their texts as props, or through a context when no props are available.
- Internal links always carry the locale and a trailing slash: ``href={`/${locale}/resume/`}``.
- `locales/en.ts` and `locales/fr.ts` keep exactly the same keys; the type check enforces it.
- Texts rendered with `dangerouslySetInnerHTML` must come from the `locales/` files only. Never pass external data through them.
- Details: [docs/architecture/i18n.md](docs/architecture/i18n.md).

## Design

- The design charter ([docs/redesign/charte-graphique-valentinbourreau.md](docs/redesign/charte-graphique-valentinbourreau.md)) is authoritative for the look of the site. When in doubt, apply the most sober rule.
- Colours are the eight Eucalyptus tokens only (`bg-bg`, `bg-surface`, `border-line`, `text-muted`, `text-text2`, `text-text`, `text-accent`, `bg-accent text-on-accent`). The Tailwind palette is not available. The accent marks what is live (current status, ongoing work, main action, hover, focus): never running text, never decoration.
- Geist for what is read, Geist Mono (lowercase) for what is scanned. No other font.
- Font sizes come from the nine `type-*` styles of `app/globals.css` only (`type-display` … `type-meta`, plus `type-display-compact` for post titles): never `text-[19px]`, `text-[clamp(…)]` or `text-sm`. A unit test fails otherwise. Headings go through `HeadingComponent`: one `h1` per page in `display`; `h2` in `label` on index pages, in `title` on document pages; every `h3` in `subhead`; no `h4`.
- Every page opens with `PageHeaderComponent` and follows one of two templates: index (sections) or document (`DocumentLayoutComponent`: summary on the left, always). Every page ends with `SiteFooterComponent`. The portrait is on the home page and the resume only.
- Radius 2 px (`rounded`), 6 px for the portrait only. No shadow, no gradient, no blur, no emoji, no decorative icon: glyphs (`●`, `○`, `→`, `+`, `~/`) and words instead.
- No entrance animation. Nothing starts at `opacity: 0`. Motion is limited to colour transitions of 150 ms.
- Theme changes go in `app/globals.css` (there is no `tailwind.config.ts`).
- Details: [docs/frontend/styling.md](docs/frontend/styling.md).

## Content

- The texts of the home page and the resume are in `locales/content/fr.ts` and `en.ts`, typed by `lib/models/content.ts`. French is the reference and follows the brief word for word ([docs/redesign/brief.md](docs/redesign/brief.md)); English mirrors it entry for entry. Do not reword them without Valentin.
- One title everywhere ("Ingénieur front-end senior"). "Freelance" is a status shown apart. No stated objective, no level labels, no framework versions in the hero.
- French typography: `’`, a non-breaking space (written `\u00a0`) before `: ; ! ?` and between a number and its unit, `–` in ranges, `→` in changelog dates, real lists.
- Never hardcode a visible text in a component.
- `lib/constants/` holds the facts used by the structured data. Keep them in line with the page texts.
- The domain, the site name and the portrait come from `lib/constants/site.ts` only.
- When the visible content of a page changes, bump its `updatedAt` in `lib/constants/pages.ts`.
- Details: [docs/content/resume-data.md](docs/content/resume-data.md).

## Pages, SEO and structured data

- Structured data is part of adding a page, not a follow-up. A new page is declared in `PAGES`, gets its texts in `getPageTexts`, its graph in `PAGE_GRAPHS`, and renders `<JsonLdComponent page="…" />`. The type check fails until all of it exists.
- Structured data describes only what is visible on the page, and is generated from the data and the dictionaries, never written by hand.
- One `Person` and one `WebSite` node for the whole site, referenced by `@id`. `WebSite` on the home page only. A `BreadcrumbList` on every page except the home page.
- Meta descriptions stay under 155 characters.
- The legal page (`/legal/`) describes how visitor data is handled. Adding, removing or changing anything that touches it (analytics, a resource from another origin, a form, a cookie) updates its texts in both languages and its `updatedAt`.
- The legal texts (`locales/legal/`) follow the handoff in `docs/legal-handoff/content/` word for word, with French typography added; a test compares them. The terms of service (`/cgv/`) exist in French and in English: `cgv.en.md` is the single source of the English text (lotus reuses it for English quotes), and the French version prevails (article 20). A new version of the terms adds its PDFs in `public/cgv/` (`cgp-<version>.pdf`, `cgp-<version>-en.pdf`, the English one printed by `npm run cgv:pdf -- en`) and never replaces one, because a signed quote refers to a version. Details: [docs/features/legal-pages.md](docs/features/legal-pages.md).
- A generated file served at the root without an extension (`/apple-icon`) must be excluded in the `matcher` of `proxy.ts`.
- A post is an MDX file in `content/posts/<slug>/<locale>.mdx`, its images in `public/posts/<slug>/` (WebP at 2x; a `src` without extension is a `-jour`/`-nuit` pair), an entry in `POSTS` (`lib/constants/posts.ts`, plain data, most recent first) and its loader in `POST_BODIES` (`lib/constants/post-bodies.ts`). Reading time, word count and summary are computed from the MDX source, never written. A slug never changes once published. Valentin writes the posts: never publish a text under his name that he did not write, and never reword one.
- A post uses only the components registered in `mdx-components.tsx` (`components/post-*/`, Server Components, props documented in `docs/features/posts.md`); a test checks every MDX file against them and against its images.
- `draft: true` shows a post in development and on Vercel previews (`VERCEL_ENV=preview`), never in production, and never in the sitemap or the feed.
- `visibility: "protected"` puts a post online behind a password: listed nowhere, `noindex`, its page, sharing image and images gated by `proxy.ts` (two literal `matcher` lines per post, checked by a test) with a signed cookie (`PROTECTED_POSTS_PASSWORD`, `PROTECTED_POSTS_SECRET`). Nothing sent to the browser on another page may name it. Making it public is removing `visibility`.
- The image optimizer is limited to the portrait (`images.localPatterns`): post images are served unoptimized, so that the optimizer never reads a protected image.
- The resume PDFs (`public/cv-fr.pdf`, `public/cv-en.pdf`) are printed from `/[locale]/resume/print/` by `npm run build && npm run cv:pdf` and committed. Regenerate them after any change to the resume content; each must stay on one A4 page.
- Details and the checklist: [docs/features/pages.md](docs/features/pages.md), [docs/features/seo.md](docs/features/seo.md), [docs/features/posts.md](docs/features/posts.md), [docs/features/resume-pdf.md](docs/features/resume-pdf.md).

## Components

- Server Component by default. `"use client"` only for what needs the browser.
- shadcn/ui first. A button, card, badge, separator or breadcrumb is the shadcn component (`components/ui/`, added with `npx shadcn@latest add <component>`), restyled in its own file to follow the charter. Write a component from scratch only when shadcn has no equivalent, and say why in a comment.
- The shadcn theme is mapped onto the Eucalyptus tokens in `app/globals.css`, so a new component comes out in the charter's colours. Two names differ from shadcn's defaults: `muted` and `accent` are the charter's text and accent colours, not background tints (use `surface` for a tinted background). After adding a component, remove its shadows, set its radius to `rounded` and check both modes.
- Two deliberate exceptions: the portrait uses `next/image`, not shadcn `Avatar` (which would lose image optimisation and delay the largest paint), and the header nav is a plain list of links, not `NavigationMenu` (client code for static links).
- Components hold no text: content comes in as typed props.
- The header nav stays visible on phones (it wraps). Check the header at 375 px after changing it.
- Every link and button has an accessible name; an `aria-label` contains the visible text.
- Delete a component, a constant or a package when its last usage goes away.
- Every component is shown on the design system page of the admin (`/admin/design-system/`): a new one gets its specimen in `app/admin/design-system/_components/registry.tsx` and its file in `coverage.ts` in the same change, or a reason in `SKIPPED_FILES`. A unit test fails otherwise.
- Details: [docs/frontend/components.md](docs/frontend/components.md), [docs/frontend/design-system.md](docs/frontend/design-system.md).

## Contact form, database, admin and audience figures

- Leads go through `POST /api/contact/`: Vercel BotID, honeypot and time trap, validation on the server, then Neon. A form is sent with `fetch`, never as a native HTML post. Every protected route is declared in `initBotId` and calls `checkBotId()`.
- Every error shown to a visitor or to the admin is a shadcn toast (`toast` from `sonner`), with its text in the dictionaries. No inline error messages.
- SQL always goes through the `sql` template tag of the Neon driver. Never concatenate.
- No environment variable value in the code, the logs, an answer or the docs: names only. No name, e-mail address or message in the logs.
- The stored values of `LEAD_NEEDS`, `LEAD_TIMELINES`, `LEAD_STATUSES`, `LOTUS_STATUSES` and `FUNNEL_EVENTS` are never renamed.
- Conversion is measured with anonymous daily counters only (`POST /api/events/`, table `funnel_daily`): no identifier, nothing written to the visitor's browser. The origin of a lead is kept in memory until the form is sent.
- Every admin page stays under `/admin` and calls `requireAdmin()`; every admin Server Action and route calls `assertAdmin()`. Never rely on the proxy alone. Admin pages are `noindex`, `no-store` and `force-dynamic`.
- A schema change is made in `db/schema.sql` and recorded in the change log of `docs/database/schema.md`. It is additive and safe to run again, and it is applied (`npm run db:setup`) before the code that needs it is deployed.
- Leads are forwarded to lotus after the response (`after()`), through a webhook signed with `LOTUS_WEBHOOK_SECRET`; the contract lives in the lotus repository (`docs/integration-site.md`). The answer to the visitor never depends on lotus. `lotus_status` is `synced` only when lotus answered 200 or 201; the daily cron sends again what is `pending`. Never point a local or preview build at the production lotus.
- Audience figures are read from Neon, never live from Vercel: the daily cron (`vercel.json`) copies them because Vercel keeps one month only. Only aggregated counts are stored. The snapshot must stay idempotent.
- A cron route lives under `/api/cron/`, starts with `isCronAuthorized` (`lib/cron/auth.ts`), which checks `Authorization: Bearer <CRON_SECRET>` in constant time and is closed without the variable, and is declared in `vercel.json`.
- `LEADS_MEMORY_STORE=1` forces the in-memory stores: use it to test a production build locally, because `.env.local` points to the production database.
- Any change to what is collected, stored or sent to a provider updates the legal page in both languages.
- Details: [docs/features/contact-form.md](docs/features/contact-form.md), [docs/features/admin.md](docs/features/admin.md), [docs/features/analytics.md](docs/features/analytics.md), [docs/features/conversion.md](docs/features/conversion.md), [docs/features/lotus-sync.md](docs/features/lotus-sync.md), [docs/database/neon.md](docs/database/neon.md).

## Code style

- `type` rather than `interface`, `T[]` rather than `Array<T>`, inline type imports.
- No `any`, no non-null assertion, `??` rather than `||` for defaults.
- A stable `key` in lists, never the array index. Plain functions rather than a class used as a namespace.
- No `eslint-disable` comment without a reason written next to it.
- Details: [docs/development/code-quality.md](docs/development/code-quality.md).

## Security

- The CSP in `next.config.ts` allows same-origin resources only. A third-party script, iframe, font, remote image or browser-side network call needs the policy opened first: do it explicitly, document it, and record it in the request log.
- Details: [docs/architecture/security.md](docs/architecture/security.md).
