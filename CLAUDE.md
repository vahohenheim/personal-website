# personal-website

Personal website of Valentin Bourreau (`valentinbourreau.com`): a home page and an online resume, in English and French. Fully static: no database, no form, no environment variable.

Stack: Next.js 16 (App Router, Turbopack), React 19, strict TypeScript 6, Tailwind CSS v4, shadcn/ui (Radix), `dayjs` for dates, `motion` for reveal animations, Vercel Analytics. Translations use no library: plain dictionaries read through `next/root-params`.

**Language:** everything written in this repository (docs, comments, commit messages) is in English.

**Next.js docs:** the version-matched documentation ships in `node_modules/next/dist/docs/`. Read the relevant guide there before changing routing, caching, metadata or config. `AGENTS.md` is generated by `next dev`; do not edit it.

## Commands

- `npm run dev`: local server.
- `npm run build`: production build. This is the reference check before shipping.
- `npm run typecheck`: `next typegen` then `tsc --noEmit`. The typegen step is required: `LayoutProps`, `PageProps` and the `next/root-params` exports are generated types.
- `npm run lint:check`: ESLint without changes. `npm run lint` applies `--fix`.
- `npm run format`: Prettier on the whole repository. `npm run format:check` verifies it.
- There are no automated tests.

Before handing work back: `typecheck`, `lint:check`, `format:check` and `build` must all pass.

## Structure

`app/` holds routing only. Everything else lives in `components/`, `lib/` and `locales/`.

```
app/
  globals.css               Tailwind v4 + theme (CSS variables, light / dark)
  manifest.ts, robots.ts, sitemap.ts
  [locale]/                 Root segment: every route is under a locale
    layout.tsx              Root layout: <html>, Geist font, theme, header, footer, analytics
    page.tsx                Home
    error.tsx               Error boundary (Client Component), translated
    not-found.tsx           Translated 404, rendered inside the layout
    [...rest]/page.tsx      Catch-all that sends unknown URLs to not-found.tsx
    resume/
      page.tsx              Resume
      _components/          Resume-only components (private folder, never routed)
components/                 Components shared across pages
  ui/                       shadcn/ui components
  icons/                    SVGs as React components (companies/, social-networks/, logo)
  jsonld/                   <script type="application/ld+json"> tags
lib/
  i18n/                     config.ts (locales), dictionaries.ts (getLocale, getDictionary),
                            error-messages.tsx (context for error.tsx)
  models/                   Types and enums (enums are used as identifiers)
  constants/                Site data, typed by models/ (site.ts holds the domain and avatar)
  helpers/                  metadata.ts (meta tags, alternates), json-ld/ (schema.org)
  utils/                    cn.ts, format-date-difference.ts
locales/                    en.ts, fr.ts (all visible texts)
proxy.ts                    Redirects URLs without a locale to /en or /fr
public/                     Images
```

Import alias: `@/*` points to the repository root. Use it for every import that leaves the current folder.

## Routing and translations

- Two pages: `/[locale]/` and `/[locale]/resume/`. Locales are declared once, in `lib/i18n/config.ts` (`LOCALES`, `DEFAULT_LOCALE`, `Locale`, `hasLocale`). `trailingSlash` is enabled.
- `app/[locale]/layout.tsx` is the root layout. There is no `app/layout.tsx`, which makes `locale` a root parameter.
- `proxy.ts` (the Next.js 16 name for middleware) only handles URLs that have no locale: it redirects to the language saved in the `NEXT_LOCALE` cookie, else to the best match of `Accept-Language`, else to `en`. The cookie is written by `LanguageToggle`.
- Pages are statically generated (`generateStaticParams` in the root layout). Only the catch-all route is dynamic.
- In any Server Component or server-side helper, call `getLocale()` and `getDictionary()` from `@/lib/i18n/dictionaries`. They read the locale through `next/root-params`, so no `locale` prop is passed down and pages do not read `params`.
- Client Components cannot call them. Pass the locale or the texts they need as props (`LanguageToggle`), or through a context when no props are available (`error.tsx` reads `ErrorMessagesProvider`, mounted in the root layout).
- Internal links always carry the locale and the trailing slash: ``href={`/${locale}/resume/`}``. A link without a locale costs a redirect through `proxy.ts`.
- `locales/en.ts` defines the `Dictionary` type and `locales/fr.ts` is typed with it: a missing or extra key in either file fails `typecheck` and the build.
- An unknown URL under a locale reaches `[...rest]/page.tsx`, which calls `notFound()` and renders `not-found.tsx` in the right language with a 404 status.
- Some texts contain HTML (`<b>`, `<br/>`) and are rendered with `dangerouslySetInnerHTML` (`Cover`, `Expertise`, `Mission`, `Duration`, `Heading`). This is acceptable only because those texts come from the `locales/` files. Never pass external data through them.

Adding a locale: add it to `LOCALES` and `OPEN_GRAPH_LOCALES` in `lib/i18n/config.ts`, create `locales/<code>.ts` typed as `Dictionary`, register it in `lib/i18n/dictionaries.ts`, and add its entry to `LANGUAGES` in `components/language-toggle/language-toggle.tsx`. Routes, metadata alternates and the sitemap follow `LOCALES`.

Adding a page: create `app/[locale]/<name>/page.tsx`, add it to `PAGES` in `lib/helpers/metadata.ts` (this feeds the canonical URL, the `hreflang` alternates and the sitemap), export `generateMetadata` from the page, and add its texts to both locale files.

## Content: data and identifiers

Content is split in two: structure (dates, links, order) lives in `lib/constants/`, texts live in `locales/`. The link between them is the identifier, defined by an enum in `lib/models/`. The enum value is the dictionary key, so texts are read by indexing: `dictionary.companies.list[company.id].name`.

| Data              | Model                                   | Constant                                     | Dictionary keys                                                    |
| ----------------- | --------------------------------------- | -------------------------------------------- | ------------------------------------------------------------------ |
| Companies         | `CompanyId`                             | `COMPANIES` (`companies.ts`)                 | `companies.list.<id>.name`                                         |
| Experiences       | `Experience`                            | `EXPERIENCES` (`experiences.ts`)             | none, everything goes through the company and the missions         |
| Missions          | `MissionId`                             | `MISSIONS` (`experiences.ts`)                | `experiences.roles.<id>.content`                                   |
| Roles             | `RoleId`                                | inside each mission                          | `roles.<id>`                                                       |
| Qualifications    | `QualificationId`, `QualificationLevel` | `QUALIFICATIONS` (`qualifications.ts`)       | `qualifications.list.<id>.label`, `qualifications.level.<id>.name` |
| Schools           | `SchoolId`                              | `SCHOOLS` (`qualifications.ts`)              | `schools.list.<id>.name`                                           |
| Languages         | `LanguageId`, `LanguageLevel`           | `USER_LANGUAGES` (`languages.ts`)            | `languages.list.<id>.name`, `languages.level.<id>.name`            |
| Expertises        | `ExpertiseId`                           | `EXPERTISES` (`resume.ts`)                   | `expertises.list.<id>.{label,title,text}`                          |
| Personal projects | `PersonalProjectId`                     | `PERSONAL_PROJECTS` (`personal-projects.ts`) | `personal-projects.list.<id>.{title,description}`                  |
| Social networks   | `SocialNetworkType`                     | `SOCIAL_NETWORKS` (`social-network.ts`)      | none                                                               |

Rules:

- Never hardcode a visible text in a component: add it to `locales/en.ts` and `locales/fr.ts`.
- Reference data through the enum (`MISSIONS[MissionId.EP_LEAD_FRONT_END]`), not through the string.
- `COMPANIES` and `MISSIONS` are `Record<Id, …>`: adding an enum value forces you to add the entry, and indexing the dictionary with the enum forces you to add the text.
- `EXPERIENCES` is displayed in array order, most recent first. `endDate: 'today'` marks the current position.
- A mission shows its own duration only when it has both `startDate` and `endDate` (used when one experience holds several missions).
- Dates use the ISO format `YYYY-MM-DD`.
- The domain, site name and avatar come from `lib/constants/site.ts`. Do not write them anywhere else. The portrait is `public/avatar.jpg` (square, 480 px): replace the file to change it.

Adding an experience:

1. `lib/models/company.ts`: a value in `CompanyId`. `lib/constants/companies.ts`: an entry in `COMPANIES`.
2. `components/icons/companies/<id>.tsx`: the logo as an SVG component (`IconProps` props, colour through `className` and `fill`). The file name must be exactly the `CompanyId` value, because `CompanyIconComponent` loads it with a dynamic `import()`.
3. `lib/models/mission.ts`: a value in `MissionId`. `lib/constants/experiences.ts`: an entry in `MISSIONS`, then in `EXPERIENCES`.
4. `locales/en.ts` and `locales/fr.ts`: `companies.list.<id>.name` and `experiences.roles.<mission-id>.content`.
5. The company also appears in the logo strip on the home page (`Object.values(COMPANIES)`, in declaration order).

## Components

- One folder per component, in kebab-case: `components/<name>/<name>.tsx`. Separately typed props go in `<name>.model.ts`, constants in `<name>.constants.ts`, hooks in `<name>.hook.ts`.
- Default export, named `<Name>Component`.
- A component used by a single page lives in that page's `_components/` private folder. A shared component lives in the root `components/`.
- Server Component by default. `'use client'` only for interactivity (`LanguageToggle`, `ModeToggle`, `Appear`, `ThemeProvider`).
- Simple interface components: shadcn/ui first (`components/ui/`, `new-york` style, added with `npx shadcn@latest add <component>`). Here each shadcn component sits in its own folder (`components/ui/button/button.tsx`): move the generated file and import from `@/components/ui/button/button`.
- Only the shadcn components in use are kept (`badge`, `button`, `dropdown-menu`, `navigation-menu`). Add one back when it is needed, do not keep unused ones: each pins a Radix dependency.
- A link that looks like a button is `<Button asChild><Link href="…">…</Link></Button>`, and a navigation link is `<NavigationMenuLink asChild><Link …/></NavigationMenuLink>`. Never nest a `<button>` or an `<a>` inside a `<Link>`.
- Conditional classes with `cn()` (`@/lib/utils/cn`).
- `SectionComponent` gives the site content width (900 px) and the section title. `AppearComponent` handles reveal on scroll.
- Header menu: `components/header/header.constants.ts` (paths without the locale, with a trailing slash). The `retrospectives` and `posts` entries are commented out there; their translations already exist.
- Delete a component when its last usage goes away.

## Styling

- Tailwind v4, configured in `app/globals.css` (`@theme inline`, CSS variables, class-based `dark` variant). There is no `tailwind.config.ts`: every theme change goes in `globals.css`.
- Light / dark theme through `next-themes` (`attribute="class"`, system default). Use the tokens (`bg-background`, `text-foreground`, `text-muted-foreground`…) and provide a `dark:` variant for any hardcoded colour.
- Geist font through `next/font/google` in the root layout.
- Prettier formats everything (4 spaces, single quotes, 120 columns) and sorts Tailwind classes.

## SEO

- Meta tags: `getPageMetadata('<page>')` (`lib/helpers/metadata.ts`) returns the translated title and description, the canonical URL, the `hreflang` alternates and the Open Graph data. Texts are in `metadata.*` and `resume.metadata.*`.
- Structured data: `JsonLd` (`lib/helpers/json-ld/`), data in `lib/constants/structured-data.ts`, rendered by `components/jsonld/` with `<` escaped, as the Next.js JSON-LD guide requires.
- `app/sitemap.ts` is generated from `PAGES` and `LOCALES`.

## Security

`next.config.ts` sets a strict CSP and security headers on every route. Consequences:

- Scripts, styles and fonts: same origin only. Images: same origin, `blob:` and `data:`.
- No remote image is allowed today (`images.remotePatterns` is not set). A remote image goes through `next/image` and needs its domain added there.
- Any third-party service (script, iframe, font, network call from the browser) first requires opening the CSP. Do it explicitly and record it in the request log.
